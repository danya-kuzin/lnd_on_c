# Lords & Dragons

Lords & Dragons - симуляционный движок пошаговой 4X-стратегии, написанный на C. Проект начался как учебная реализация правил моей собственной настольной игры и используется для практики модульного C, Linux-инструментов, моделирования игрового состояния, обработки команд и базового клиент-серверного программирования.

Текущая версия - играбельный консольный прототип с отделенным игровым ядром, CLI-интерфейсом и экспериментальным TCP client-server слоем.

## Ключевые особенности

Что было сделано (задачи и подсистемы):

- Система была спроектированна с жестким разделением ответственности (ядро симуляции, сетевой интерфейс, CLI-слой). Игровая логика полностью независима от подсистемы ввода-вывода.
- Были реализованы структуры данных для управления состоянием игрового мира (гексагональная карта 16x8, сущности игроков, юнитов, ресурсов и механики пошаговых раундов).
- Была написана система детерминированного расчета игровых механик (перемещение, расчет зон видимости, формулы ближнего/дальнего боя) и rule-based валидатор входящих команд для защиты от некорректных действий клиентов.
- Был разработал сетевой протокол на базе TCP-сокетов, где сервер выступает единым источником правды (Single Source of Truth), сохраняя состояние сессии и синхронизируя его с клиентами.

## Текущая стадия

Проект находится на стадии вертикального прототипа.

Реализовано:

- CLI-игровой цикл для 2-4 игроков.
- Пять типов юнитов: мечник, копейщик, лучник, конница и разведчик.
- Порядок ходов, раунды и команда `end`.
- Экономика золота и доход с деревень.
- Валидация перемещения: границы карты, существующие гексы, занятые клетки, владение юнитом и очки перемещения.
- Валидация боя: владение атакующим юнитом, дальность атаки, одна атака за ход и удаление погибших юнитов.
- ASCII-представление состояния карты для CLI-версии.
- TCP server/client прототип для локального тестирования через `127.0.0.1`.

Пока не реализовано:

- Графический интерфейс на Raylib.
- Система сохранения и загрузки игры.
- Полноценный туман войны.
- Полные боевые модификаторы от ландшафта.
- Полное алхимическое дерево из правил настольной игры.

## Сборка

Целевая среда разработки - Linux или WSL Ubuntu.

Установка базовых инструментов:

```bash
sudo apt update
sudo apt install build-essential make
```

Собрать все:

```bash
make
```

Собрать и запустить локальную CLI-версию:

```bash
make run-cli
```

Очистить артефакты сборки:

```bash
make clean
```

## TCP-прототип

Запустить сервер в одном терминале:

```bash
make run-server
```

Запустить двух клиентов в двух других терминалах:

```bash
make run-client
```

Текущий сервер намеренно сделан простым:

- привязывается к `127.0.0.1`;
- ожидает ровно двух клиентов;
- использует текстовые команды;
- сервер владеет авторитетным состоянием игры.

## Команды

CLI и сервер используют один и тот же базовый язык команд:

```text
help
status
create <mech|kop|arch|cav|scout>
move <unit_id> <x> <y>
attack <attacker_id> <defender_id>
end
finish
```

Примеры:

```text
create scout
move 1 5 2
attack 2 1
end
status
```

## Архитектура

Основные модули:

- `game.*` - общее состояние игры и правила ядра.
- `game_create_unit.c` - создание юнитов и проверки экономики.
- `game_move.c` - перемещение, проверка карты и захват деревень.
- `game_attack.c` - расчет боя и результатов атаки.
- `game_end_turn.c` - смена хода, сброс перемещения и доход с деревень.
- `cli_*` - локальный консольный интерфейс.
- `server_*` - серверные обработчики команд.
- `lnd_server.c` / `lnd_client.c` - TCP server/client прототип.
- `net_common.*` - общие socket helper-функции.

Главная архитектурная идея - держать игровые правила независимыми от ввода/вывода. CLI- и server-код переводят текстовые команды в вызовы `game_*` функций.
